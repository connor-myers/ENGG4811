\noindent
Static application security testing (SAST) applies static program analysis to the security of software projects. Static analysis is performed on the source code, compiled byte-code or some other intermediate representation of the source code \cite{NielsonFlemming2005Popa}. \\

\noindent
SAST tools have become a widespread method for improving the security of large software projects. Popular SAST tools include: SonarQube \cite{sonarqube}, SpotBugs \cite{spotbugs}, Snyk Code \cite{snykcode}, and Facebook's Infer \cite{infer}. SAST tools have become commonly used in organisations at all software development life cycle stages. They have been demonstrated to be highly effective in identifying defects in programs compared to other methods, such as manual inspection \cite{Nichols2020}. \\

\noindent
SAST tools, by their very nature, produce a conservative program analysis. As a result of this, false positives are a common issue with these tools. False positives are not ideal as manual inspection is required to identify the genuine defects from these false positives, leading to increased time and labour cost, which are the same measures SAST tools aim to minimise. Manual configuration of SAST tools is often required to reduce the rate of false positives and produce a more effecitve and useful analysis for specific software projects \cite{ZampettiFiorella2017HOSP}.
