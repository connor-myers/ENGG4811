\section{Taint Analysis}

Taint analysis is a type of information-flow analysis that considers all user-inputted data (sources) as malicious and follows the flow of this tainted data to determine if it reaches a security-sensitive operation (sinks) \cite{effective-taint-analysis} (e.g., a function call or SQL query). \\ 

\noindent
Most taint analysis tools also consider another class in addition to sources and sinks known as sanitisers. A sanitiser is a method that makes untrusted user data safe to flow into sinks. A taint analysis tool will consider all sources of tainted data, follow their flow in a program, and raise a warning if a source can reach a sink without first going through a sanitiser. \\

\noindent
Taint analysis can be performed statically or dynamically (i.e., on some representation of the source code or as a running program), although it is typically done statically. Common tools for performing static taint analysis include Facebook's Infer \cite{infer} and SonarQube \cite{sonarqube}. \\

\noindent
Consider the motivating example in Figure \ref{figure-taint-example} which shows a simple SQL injection vulnerability in Java.\\

\begin{figure}[H]
    \lstinputlisting[style=mystyle, language=Java]{code/path-traversal-bad.java}
    \caption{A contrived example of an SQL injection vulnerability that would be detected by a taint analysis tool.}
    \label{figure-taint-example}
\end{figure}

\noindent
From Figure \ref{figure-taint-example}, it is clear that getParameter() is a source. This is because getParameter() retrieves the value of a parameter in an HTTP request, which the user can set arbitrarily. Because the user can set the parameter, the variable `name' in this code is considered tainted. Taint analysis tools do not implicitly know what methods are security sensitive. Taint analysis tools have a database of methods (labelled as sources, sinks, and sanitisers) from commonly used libraries in which to conduct the analysis on\footnote{See Appendix \ref{appendix:sources} for an example of a real default configuration of source methods for the taint-analyis tool \emph{sink-tank}.}.\\

\noindent
A taint analysis tool cannot follow the flow of tainted input through a program if it does not know what input should be considered security sensitive. The default configuration of security-sensitive methods often proves insufficient for large projects and projects using niche libraries. Therefore, security analysts often manually inspect a project's code and create a configuration of security-sensitive methods specific to a particular project. Naturally, creating this custom taint analysis configuration is time-consuming and error-prone.\\

\noindent
In Figure \ref{figure-taint-example} the variable \emph{name} is included in an SQL query without its content being sanitised. Any good taint analysis tool will have getParameter() as a source and executeQuery() as a sink and therefore flag this example as an insecure dataflow. \\

\noindent
\emph{Name} should first be sanitised before it is included in the SQL query. An example of a commonly used sanitiser for SQL input is\\ org.apache.commons.lang.StringEscapeUtils.escapeSql(), which removes any SQL control characters from a string, such as `;'.\\

\noindent
While Figure \ref{figure-taint-example} is a simple and contrived example, it highlights the importance of taint analysis and the terminology used. However, the detection of this insecure dataflow is predicated by those featured security-sensitive methods (i.e. getParameter(), executeQuery(), and escapeSql()),  being included in the taint analysis tool's configuration.\\

\noindent
A taint analysis tool is only as effective as its configuration is complete. Suppose a taint analysis tool's configuration misses real security-sensitive methods in a project. In that case, the analysis generated will not be optimum and insecure dataflows will be missed. \\

\section{Deep Learning}

Deep learning is a subtopic within the broader category of machine learning whereby many layers of interconnected artificial neurons learn generalised representations of data for applications such as image classification, machine translation, autonomous vehicles, and many more \cite{LecunYann2015Dl}. Neural networks are networks of artificial neurons inspired by biological neurons.\\

\begin{figure}[h]
    \begin{center}
            \includegraphics[scale=0.65]{images/neuron_diagram.png}
    \end{center}
    \caption{Diagram of a singular neuron \cite{neuron_picture}}
    \label{neurondiagram}
\end{figure}

\noindent
Figure \ref{neurondiagram} shows a diagram of a singular neuron in a neural network, highlighting the key features of a neuron. A neuron receives input from $m$ nodes, listed above as $\{x_{0}, x_{1}, x_{2},...,x_{m}\}$. These inputs may come from other neurons in the previous layer in the network or, if this neuron is within the first layer of the hidden network, directly from the input data. Each edge (that is, each connection between an input and the neuron in question) has a \emph{weight}; the weights in the above diagram are $\{w_{j0}, w_{j1}, w_{j2},...,w_{jm}\}$. A weight is a real number associated with each neuron connection that scales the value of the input signal. \\

\noindent
After all the input values from each connecting neuron are calculated, they are summed together. Typically, although it is not shown in the above figure, each neuron has an associated bias. Bias is a value that is added to a neuron's output by default. \\

\noindent
To introduce non-linearity into the network, a neuron's sum is passed through an \emph{activation function}. A common choice of activation function is the sigmoid function, although there are many activation functions to choose from, each with its positives and negatives. \\

\noindent
Initially, the weights and biases in the network are initialised randomly. A neural network must be `trained', it is said, to set all its weights and biases in such a way that the network produces useful outputs. By feeding labelled data into the model (i.e., where the expected output is known), the weights and biases of the model can be systematically updated so that the output generated by the network for some input more closely resembles the expected output. If conducted on a sufficient number of examples on a diverse training dataset, the neural network will hopefully learn to generate accurate outputs for data it has not seen before. \\

\subsection{Neural Network Architectures}
There are a variety of architectures of neural networks. The choice of architecture is critical and fundamentally affects a model's performance.

\subsubsection{Recurrent Neural Networks}

\noindent
Natural language processing has for many years been done with Recurrent Neural Networks (RNNs)\footnote{More specifically, long short-term memory networks (LSTMs), which are a subclass of RNNs.}. \\

\noindent
RNNs were vital for natural-language processing as this neural-network architecture is capable of `memory'. In the scope of natural language processing, this means RNNs can understand the \emph{context} of words. Having a model understand context is vital because a word's position in a sentence can dramatically alter its meaning. \\

\noindent
RNNs understand context by sequentially processing an input sentence one word at a time and incorporating one word's output into processing the word after it. Since RNNs process data sequentially, options for parallelisation are limited. As a result of this, RNNs are notoriously slow \cite{patiexploring}.\\

\noindent
Furthermore, this memory of previous inputs that is maintained as the network processes an input slowly vanishes. For very long inputs, the memory created at the start of an input sequence will disappear towards the end of the sentence. As such, RNNs are not as effective on long sequences. \\

\subsubsection{Long Short Term Memory (LSTM)}

\noindent
Long short-term memory networks (LSTMs) are a subclass of RNNs that aim to reduce the problems of traditional RNNs, namely vanishing context for long inputs. LSTMs employ `gating units' to each node in a network, ensuring the contextual information generated by previous words in a sentence is maintained over longer input sequences. Unfortunately, this comes at a significant performance cost. As a result, LSTMs are notoriously slow \cite{sundermeyer2012lstm}.

\subsubsection{Transformer Architecture}
\label{transformers}

\noindent
It is not an exaggeration to say that the publishing of \emph{Attention Is All You Need} \cite{attention}, and thereby the introduction of the Transformer architecture, has completely revolutionalised natural-language processing. \\

\noindent
Perhaps the most useful property of the Transformer architecture is that they are parallelisable. With Transformers, all words of an input sentence are processed simultaneously. Transformers can more efficiently exploit GPU hardware \cite{gpu-parallel}, which excels at parallelised workflows. Because of this, Transformers see extraordinary performance improvements compared to other neural network architectures \cite{attention}.\\

\noindent
Furthermore, because all tokens of an input sequence are processed simultaneously, Transformers can understand context much better than RRNs. Transformers have been shown to consistently outperform RNNs\footnote{The literature suggests one case this does not hold is when only a small amount of training data is available. In that case, LSTMs have been shown to outperform Transformers \cite{transformer-bad}.} in both training time and efficacy in many downstream tasks \cite{attention}\cite{asr-rnn-transformer}.\\

\label{token_limit}
\noindent
There is one major caveat to this improved performance. Unlike RNNs, which can have an input sequence of any length, Transformers require a fixed-length input. All input sequences must have the same length, and there is a maximum length an input sequence can be. BERT, and other models based on it, such as RoBERTa, have a maximum input length of 512 tokens \cite{bert}. This is not an issue for most use cases, as 512 tokens are usually sufficient. \\

\subsubsection{Embeddings}

\noindent
For this thesis, embeddings can be considered as vector representations of tokens. That is, they map a token to a point in vector space. Related tokens and tokens with similar meanings will map more closely together in vector space. \\

%\noindent
%Naturally, how models based on the transformer architecture do this is out-of-scope for this thesis, however it corresponds to the `Multi-head Attention' block in Figure \ref{transformer}.\\

\noindent
For example, the pre-trained model CodeBERT has 768 nodes in its output layer (i.e. the last layer of its hidden network) \cite{CodeBERT}. The sequence of numbers created by the final values of those 768 nodes is the embedding for that input token. This means the output for each token fed into CodeBERT is an embedding, and a tensor, of size $n = 768$.\\

%In the case of codeBERT, there is some additional embedding information included in the embedding in addition to the token embedding. These additional embeddings are the \emph{segment} embeddings and \emph{positional} embeddings. The segment embedding provides information whether the embedding is part of the code or natural-language segment of the input. And, the positional embedding indicates where the token the embedding is for was located in the input sequence. The token embedding, segments embedding, and positional embedding are added elementwise to produce the final embedding for a given input token. \\

\subsection{Sentence Embeddings}
\label{embedding}
\noindent
For some input sequence of $n$ tokens, CodeBERT will therefore produce $n$ embeddings, each of size $768$. Most downstream tasks are performed on an input sequence, not an individual token. As such, the embeddings of each token should be combined in such a way as to generate a new embedding that contains information pertaining to \emph{all} the tokens. This is known as a sentence embedding. Creating sentence embeddings from token embeddings is known as \emph{pooling}, and various strategies exist to perform this. We will discuss the two most common techniques.

\begin{enumerate}
    \item \textbf{Mean-pooling:} Each of the $n$ token embeddings are added together and divided by $n$ (element-wise). That is, the \emph{average} embedding is calculated. 
  
    \item \textbf{CLS-pooling:} A special token (typically denoted [CLS]) is included as the first token of an input sequence. As a result of how Transformers work, this token will include information regarding the entire input sequence. To get the sentence embedding for an input sequence, we treat the token embedding of the [CLS] token as the embedding for the entire sequence.
\end{enumerate}

\label{loss}

\noindent
Loss is a measure of how incorrect a model's prediction is. Loss is used both in the context of a single input and sequence of inputs \cite[p.~11]{python-machine-learning}. Unintuitively, neural network optimisation algorithms do not optimise for accuracy. Instead, they aim to reduce loss as much as possible. A high accuracy usually correlates with low loss. However, it is possible for this not to be the case. \\ 

% \noindent
% For instance, we can have a model that is extremely accurate with its answers but not very confident, i.e., a high loss. For example, if we have a classifier model and generate the final probabilities, our final answer is whichever probability is greatest. However if our model responds with probabilities that look like: $[0.25, 0.25, 0.24, 0.26]$, where each of these values is the probability of the input sequence being one of the labels in our dataset. Technically, the model has predicted our input sequence was the 4th class, as it has a probablity of $0.26$. Even if this predicition is correct, however, it is far from ideal as we would expect a perfect model, in the case of the 4th label indeed being correct, to output $[0.0,0.0,0.0,1.0]$. Obviously no model would perform \emph{that} well, but the sentiment stands that our model should be able to \emph{confidently} predict its answers. That way, we can be reassured our model is learning \emph{generalised} representations of the data and will be able to perform effectively on real-world data it has not yet seen before. In summary: not only do we want our model to be accurate, we also want it to be confident in its answer.\\

\noindent
Loss is calculated using a loss function. Just as with activation functions, there are many loss functions, each with pros and cons. What loss function is used has significant consequences for the final performance of a model. For example, for multi-label classification tasks, the cross-entropy loss function is typically used \cite[p.~17]{AggarwalCharuC2018Nnad}.\\

\section{Support Vector Machines}

\noindent
We have spent a considerable amount of time discussing complex and state-of-the-art technologies for machine learning. To properly evaluate these complex models for this thesis, it would be beneficial to have a more simplistic model to compare results. One such architecture that fits this description is Support Vector Machines (SVMs). SVMs were developed in the 90s and are a standard tool for classification tasks.\\ 

\noindent
SVMs take in as input data with $n$ number of features and one of two labels, where each feature corresponds to a dimension in an n-dimensional feature plane. SVMs calculate a `hyperplane' such that the data points from the two labels are partitioned to either side of that hyperplane \cite[p.~5]{AbeShigeo2005SVMf}. Furthermore, this hyperplane is optimised in such a way that the distance between the hyperplane and the `support' data (i.e., the two data points from opposite labels that are closest to each other) is maximised \cite{berwick2003idiot}. Figure \ref{hyperplane-image} shows a visual representation of a hyperplane partitioning two sets of labelled data. \\

% \noindent
% As will become evident later in this thesis, feature-planes with dimensions much larger than 2 or 3 will be used. Clearly, a $767$ dimension hyperplane partitioning a $768$ dimensional feature-plane is impossible to conceive, so this lower-dimensional analogy will have to suffice.\\

\begin{figure}
    \includegraphics[scale=0.65]{images/hyperplane.png}
    \caption{An example of a hyperplane dividing two sets of labeled data in $n=2$ and $n=3$ dimensions \cite{hyperplane}.}
    \label{hyperplane-image}
\end{figure}

\noindent
Inherently, SVMs perform \emph{binary} classification, whereas this task has $4$ labels to classify on. Thankfully, SVMs can be used for multilabel classification. This can be achieved through several techniques, but a \emph{one-versus-the-rest} approach will be used for this thesis. \\

\noindent
In one-versus-the-rest classification, $K$ number of binary classifiers are created, where $K$ is the number of different labels to classify over. Each classifier classifies the data points as being part of the $K_{ith}$ label or as one of the other $K-1$ remaining labels \cite[p.~182]{BishopChristopherM2006Pram}. Input data is classified by classifying an input using each of the $K$ classifiers and selecting the label for which the corresponding classifier produced the most confident result \cite[p.~338]{BishopChristopherM2006Pram}.\\

\subsection{Term Frequency-Inverse Document Frequency}
\label{tf-idf}

Our naive model will use term-frequency inverse-document-frequency (tf-idf) to extract features for the SVM classifier. There are two aspects to tf-idf --- term-frequency and inverse document frequency. \\

\noindent
Term frequency is a measure of how often a word appears in a text. More specifically, it is \emph{proportional} to the number of times the term appears. This is because the term frequency is typically normalised by dividing the number of occurrences of a term by the frequency of the most used term in a text. So, the most frequent term in a document will have a term frequency of $1.0$, and all other terms will have a term frequency inside $\left[0.0, 1.0\right]$ \cite[p.~8]{leskovec_rajaraman_ullman_2014}. \\

\noindent
Inverse-document-frequency (idf) is an additional metric that aims to reduce the final tf-idf value for terms common in texts for all labels. For instance, the word `the' will likely have the highest term-frequency in all labels simply because it is the most common word in English. However, it is equally true that `the' is not important in classification because \emph{all} texts, regardless of label, feature it. Idf is calculated with the following equation: $ IDF_{i} = \log_{2}\left(\frac{N}{n_{i}}\right)$, where $IDF_{i}$ is the idf of the $i_{ith}$ term, $N$ is the number of documents in total, and $n_{i}$ is the number of documents the $i_{ith}$ term appears in. \\

\noindent
The final tf-idf value for a particular input is the product of term-frequency and inverse-document-frequency \cite[p.~8]{leskovec_rajaraman_ullman_2014}.
