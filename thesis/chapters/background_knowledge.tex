\section{Taint Analysis}

Taint analysis is a type of information-flow analysis that considers all user inputted data (sources) as malicious, and follows the flow of this `tainted' data to determine if it is used as input into a security sensitive operation (sinks) \cite{effective-taint-analysis} (e.g., a function call or SQL query). \\ 

\noindent
Most taint analyis tools also consider another class in addition to sources and sinks known as sanitisers. A sanitiser is some process (usually a method or function call) that make untrusted user data safe to flow into sinks. A taint analysis tool will consider all sources of tainted data, follow their flow in a program, and raise a warning if a source is able to reach a sink (a security sensitive operation) without first going through a sanitiser. \\

\noindent
Taint analysis can be performed statically or dynamically (i.e., on some representation of the source code, or as a running program), however is typically conducted statically. Common tools for performing static taint analysis include: Facebook's Infer\footnote{\url{https://fbinfer.com}}, and SonarQube\footnote{\url{https://www.sonarqube.org}}. Consider the motivating example in Figure \ref{figure-taint-example} which shows a simplistic SQL injection attack in Java.\\

\begin{figure}[H]
    \lstinputlisting[style=mystyle, language=Java]{code/path-traversal-bad.java}
    \caption{A contrived example of a SQL injection vulnerability that would be detected by a taint-analysis tool.}
    \label{figure-taint-example}
\end{figure}

\noindent
From Figure \ref{figure-taint-example}, we can see getParameter() is a source. This is because getParameter() retrieves the value of a parameter in a HTTP request, which can be arbitrarily set by the user. Because it can be set by the user, from a security perspective, the variable `name' in this code is considered tainted. Taint analysis tools cannot just `know' that a particular method call is a source, however. Most taint analysis tools have a database of methods (labelled as sources, sinks, and sanitisers) from commonly used libraries in which to conduct the analysis on\footnote{See Appendix \ref{sink-tank-default-source-config} for an example of a real default configuration of source methods for the taint-analyis tool \emph{sink-tank}.}. That is, a taint analysis tool cannot follow the flow of tainted input through a program if it does not know what input should be considered tainted in the first place. For larger projects, however, where there is a lot of custom written code, or niche libraries are being used, the provided dataset of sensitive methods often proves insufficient. Therefore, developers must inspect the code manually and create a list of sensitive methods particular to that project/library. Naturally, creating a custom taint analysis configuration for a particular software project is a time-consuming and laborious process that, if automated, would provide significant utility to large software projects.\\

\noindent
Furthermore, in the code example we can see this variable `name' being used to generate an SQL query which is then executed (executing an SQL query is obviously considered a security sensitive operation, i.e., a sink.) without any sort of validation that the name variable contains a legitimate or valid value. In this code, a malicious actor could decide their name is now `;DROP ALL TABLES;' and the code will happily delete the entire database. \\

\noindent
In order for this user input to be safely included in the SQL query, it first needs to be sanitised by a \emph{sanitiser}. An example of a sanitiser for input into an SQL query is org.apache.commons.lang.StringEscapeUtils.escapeSql() which will remove any SQL control characters from a string, such as `;'.\\

\noindent
While Figure \ref{figure-taint-example} is simplistic and contrived example, it highlights the importance of taint analysis and the terminology used. The example would easily be detected by any good taint analysis tool, and hence more likely to be fixed before any adverse outcomes occur. However, that is only possible because the methods being used, i.e. getParameter(), executeQuery(), and escapeSql(), are all common methods that will inevitably be listed as sources, sinks, and sanitisers respectively in any good taint analysis tool. Issues with the performance of taint-analysis tools can occur when the list of sensitive methods for a project is not complete. I.e., the taint-analysis configuration is missing real sources, sinks, and sanitisers and can therefore not generate an optimum analysis.

\section{Deep Learning}

Deep-learning is a subtopic within the broader category of machine learning whereby many layers of artificial neurons (hence `deep' learning) learn representations of data for applications such as: image classification, machine translation, autonomous vehicles, and many more \cite{LecunYann2015Dl}. Neural networks are networks of artifical neurons inspired by biological neurons, although artifical neurons do not exactly model biological neurons and their behaviour differs in many regards.\\

\begin{figure}[h]
    \begin{center}
            \includegraphics[scale=0.65]{images/neuron_diagram.png}
    \end{center}
    \caption{Diagram of a singular neuron}
    \label{neurondiagram}
\end{figure}

\noindent
Figure \ref{neurondiagram} shows a diagram of a singular neuron in a neural network, highlighting the key features of a neuron. A neuron receives input from $m$ nodes, listed above as $\{x_{0}, x_{1}, x_{2},...,x_{m}\}$. These inputs may come from other neurons inside the hidden-layer, or, if this neuron is within the first layer of the hidden-network, directly from the input layer. Each edge (that is, each connection between an input and the neuron in-question) is a \emph{weight}; the weights in the above diagram are $\{w_{j0}, w_{j1}, w_{j2},...,w_{jm}\}$. Naturally, a weight, in simplistic terms, refers to how much the input signal should be amplified or reduced (i.e., the input signal --- which is just a number --- is multiplied by the weight on each edge).\\

\noindent
After all these input values are calculated, they are summed together. Typically, although it is not shown in the above figure, each neuron has an associated bias. Bias is simply a default value for the node that will be added to the node (positive or negative) that will be added to the final sum of a node, irrespective of the input values.\\

\noindent
In order to introduce non-linearity into the network (all the operations we have discussed --- adding bias and multiplying weights --- are all linear), and thereby enable the network to learn more sophisticated representations, this summed value is passed through an \emph{activation function} before producing the final value of the neuron. A common choice of activation function is a sigmoid function, although there are many others commonly in use each having their own positives and negatives. Depending on where this node is located in the network, this output value $y_{j}$ will feed into yet another node or the final output layer.\\

\noindent
The key idea is that, initially, the weights and biases are initialised \emph{randomly}. A neural network must be \emph{trained}, it is said, so that these weights and biases are set appropriately and the model can `learn' generalised representations of data and therefore do something useful, such as classify data (e.g., image recognition) or generate new data (e.g.,machine translation). How exactly this training is done is out-of-scope for this background knowledge --- see backpropagation and gradient descent --- however for the purposes of understanding the contents of this thesis, all one needs to know is that by feeding \emph{labelled} data into the model (that is input where it is already known what the `correct' output should be), the weights and biases of the model can be systematically updated so that the output generated from the input more closely resembles the expected output.\\

\noindent
It is important to note that we do not want our weights and biases adjusting \emph{too} much for particular inputs. That is, the network is not learning general patterns but rather representations specific to the input data. This is known as \emph{overfitting}, and it will become a key problem further along in thesis topic. \\

\noindent
After training a network over a diverse (to avoid overfitting) and appropriate dataset for a sufficient number of examples, a neural network can have the weights and biases of its corresponding neurons adjusted in such a way that it can make predictions on data it has not yet seen before --- that is, it has learned \emph{general} representations of the data.\\

\noindent
So far, we have only discussed the function of one neuron in isolation. While this is critcal for a basic understanding of deep-learning as it relates to this thesis topic, it undermines the sheer scale of the models that will be employed this thesis project. One such model, CodeBERT \cite{CodeBERT}, has over 125 million parameters (that is, 125M weights and biases that need to be calibrated) and was pre-trained on a corpus of almost 10 million examples. Despite using 16 interconnected NVIDIA Tesla V100 GPUs, pre-training still took more than 6 hours. 

\subsection{Network Architectures}
There are a variety of architectures of neural networks. Choice of architecture is critical and it fundamentally effects all aspects of a model.

\subsubsection{Recurrent Neural Networks}

\noindent
Natural language processing, just one application of deep-learning, for which this thesis topic is concerned about in particular, had for many years typically been done with Recurrent Neural Networks (RNNs). More specifically, it was done with long short-term memory networks (LSTM) which are a subclass of RNNs.\\

\noindent
RNNs were vital for natural-language processing as this architecture of neural-network is capable of `memory'. That is, the output generated from previous inputs affects future inputs. For natural-language processing, what this means is that these models can understand \emph{context}. Having a model understand context is vital because, depending on where a word is used in a sentence (or where an identifier or code keyword is used in a program) it can have an entirely different meaning. \\

\noindent

\noindent
As demonstrated above, it is easy to see why models that do not have memory are simply not powerful enough for applications requiring context, such as natural-language processing. This understanding of context comes with many issues, however. RNNs understand context by feeding the output of a previous input into the next input. This means that input into an RNN must be processed linearly and options for parallelisation are limited. Due to this lack of parallelisation, RNNs cannot optimally exploit the parallel workflows that modern GPUs excel at and are therefore extremely slow and computationally expensive compared to other model architectures \cite{patiexploring}. Furthermore, this context (i.e., memory of previous inputs) that travels the network sequentially slowly vanishes. That is, for very long inputs the `context' created at the start of an input (sentence, code, etc...) may have, for all intents and purposes, disappeared by the end of the input. In other words, RNNs have a hard-time remembering context for large inputs. Furthermore, most RNNs cannot understand \emph{future} contexts. For example, it may be the case in some code that a keyword further ahead in an input affects the meaning of an input before it. Typical RNNs (excluding bidirectional RNNs\footnote{Bidirectional RNNs can understand future context, but they are extremely slow \cite{ZhangAston2021DiDL}.}) are simply not capable of learning such behaviour.

\subsubsection{Long Short Term Memory (LSTM)}

\noindent
Long short-term memory networks (LSTMs) are one methodology of having an RNN remember context for longer inputs. LSTMs accomplish this by adding `gating-units' to each node, which act to reduce the gradient vanishing and exploding problems, respectively. The exact function of how these gating units work is out of scope, however all one needs to know about them is that this longer-term memory comes at a significant performance cost. These gating-units and, by extension LSTMs, are notoriously slow to train and, in general, are extremely computationally expensive \cite{sundermeyer2012lstm}.

    \item ...

\noindent

\subsubsection{Transformer Architecture}
\label{transformers}

\noindent
It is not an exageration to say that Google's publishing of \emph{Attention Is All You Need} \cite{attention} (cited over 50,000 times), and thereby the introduction of the Transformer architecture, has completely revolutionalised not just natural-language processing, but all fields within machine-learning.\\

\noindent
Given Transformers are currently the cutting-edge technology for most machine-learning tasks, explaining exactly how they function is out-of-scope for this undergraduate thesis. With that being said, we will discuss the most critical aspects of transformers and BERT-like models in order to develop a sound enough understanding to understand this thesis topic moving forward. \\

\noindent
Perhaps the most useful property of the Transformer architecture is input processing can be parallelised. That is, all tokens of an input sequence can be processed simultaneously. This means these models can more efficiently exploit GPUs, which excel at parallelised workflows. With parallelisation built into the architecture, this translates to extraordinary performance improvements compared to traditional architectures \cite{attention}.\\

\noindent
Furthermore, because all tokens of an input sequence are processed simultaneously, Transformers can understand the context of tokens (notably, future context as well) much better than RNNs, including LSTMs. Transformers have been shown to consistently outperform RNNs\footnote{The literature suggests one case this does not hold, however, is for small amounts of data. With tasks that have very small amounts of training data, LSTMs have been shown to outperform Transformers \cite{transformer-bad}.} in both training-time and efficacy in many downstream tasks \cite{attention}\cite{asr-rnn-transformer}.\\

\noindent
There is one caveat to this improved performance; a limitation built into the Transformer architecture. Unlike RNNs, which can have an input sequence of any length, Transformers must have a fixed-length input. BERT, and other models based on it, such as RoBERTa, have a maximum input length of 512 tokens \cite{bert}. For most use-cases, this is not an issue and 512 tokens are more than enough. However for our use-case --- a classification task on Java methods --- the sequence of input tokens can quite often be longer than 512 tokens for some inputs. How our model handles input larger than 512 tokens is an important question and is surprisingly not so trivial, especially for our bimodal use-case. We will return to this question later in this thesis.\\

\subsubsection{Pre-trained Models and Fine-tuning}

\noindent
Given this thesis project is about the classification of security sensitive methods in Java, using both the code \emph{and} natural-language description (i.e., Javadoc), we require a machine learning model that can understand code and natural-language, in context. Creating and training a model that can understand code and natural-language is no easy task, and certainly not within scope of an undergraduate thesis. This is where pre-trained models come in.\\

\noindent
Pre-trained models, as the name suggests, are machine-learning models that have already been trained for some task. Typically, this task is very general and non-specific so that the model can later be \emph{fine-tuned} for a more specific, but related, task. Pre-trained models are useful because a significant number of machine-learning tasks are actually quite similar. That is, even though two downstream tasks may be different, the majority of the `knowledge' the model needs to learn for each task is shared between the two.\\

\noindent
For instance, there are many tasks that require a model to understand the relationship between natural-langauge and code. Downstream tasks requiring this knowledge include: code-search (searching for the most related code from natural-languae), code-generation (creating code from natural-language), and code-completion (taking a fragment of code and completing it). It is easy to see that all these aforementioned tasks share many aspects in common. Instead of training a new model from scratch for each of these tasks, it would be far easier to `pre-train' a model such that it learns the general task in common with all the downstream tasks (i.e., understand the relationship between natural-language and code), and then, for each downstream task, doing some extra training to make that general machine-learning model applicable for a specific downstream task, such as code-generation for example. This `extra-training' is known as \emph{fine-tuning}.\\

\noindent
Using pre-trained models enables us to avoid `doubling-up' on work that has already done and, in our-case, gain access to sophisticated models developed by large tech companies with an efficacy that would simply not be possible if we were to develop a model from scratch.\\

\label{fine-tuning}
\noindent
In the case of this thesis project, we simply need to select a pre-trained model that has been trained on both natural-language and Java code, and also understands the relationship between the two. Then, we can perform additional fine-tuning on this model so that it uses this understanding of code and natural-language to classify which Java methods are security sensitive\footnote{The process is not quite this simple. We will need to add an additional classification layer and modify the existing pre-trained model. We will return to this topic later in the thesis.}. We will still need to collect labelled examples of security sensitive methods, but we will not need to collect anywhere near as much data if we were training the model from scratch. Because the model has already been trained on the general-task of understanding natural-langauge and code, the vast majority of the work has already been done.\\

\subsubsection{Embeddings}

\noindent
For our purposes, token embeddings can be considered as vector representations of words (or word fragments). That is, they map a token to a point in vector-space. This is an important aspect of NLP as this is how NLP models understand \emph{context}, as related words will map more closely together in vector-space than disimilar words. For example, homonyms --- words spelt the same but with different meanings --- will produce embeddings that are \emph{not} close together in vector-space because, despite being the same word, they have different meanings. Naturally, how models based on the transformer architecture do this is out-of-scope for this thesis, however it corresponds to the `Multi-head Attention' block in Figure \ref{transformer}.\\

\noindent
CodeBERT, for example, has 768 nodes on the last layer of its hidden network. This means that for each token we feed into CodeBERT we receive an embedding of size 768. In the case of codeBERT, there is some additional embedding information included in the embedding in addition to the token embedding. These additional embeddings are the \emph{segment} embeddings and \emph{positional} embeddings. The segment embedding provides information whether the embedding is part of the code or natural-language segment of the input. And, the positional embedding indicates where the token the embedding is for was located in the input sequence. The token embedding, segments embedding, and positional embedding are added elementwise to produce the final embedding for a given input token. \\

\label{embedding}
\noindent
Understanding what an embedding is is critical moving forward with thesis. This output embedding, which, in the case of BERT models, will be a vector of size $n \times 768$, where $n$ is the number of input tokens into the model. How we interpret this result is very important. For instance, in order to perform a classification (i.e., label an input-sequence according to a set of pre-defined categories), that $n \times 768$ tensor needs to somehow be transformed (the technical term is `pooled') into a tensor of size 768. In other words, we need to pool the individual embeddings for each token into a singular embedding to generate an embedding for the \emph{entire} input sequence. I.e., a sequence embedding. There are numerous ways to perform this pooling; we will briefly outline three of these methods.

\begin{enumerate}
    \item \textbf{Mean-pooling:} Each of the $n$ embeddings are added together elementwise and divided by $n$. That is, the average embedding for some input sequence.
    \item \textbf{Max-pooling:} The max value of each embedding elementwise produces the final embedding. I.e., a new embedding is constructed where the value at index $i$ is the max value over all the $n$ embeddings at index $i$.
    \item \textbf{CLS-pooling:} With BERT models, you can include a special [CLS] as the first token of an input sequence. Due to how BERT works, this token will include contextual information for the \emph{entire} sequence embedding. So, to produce the final 768-size embedding for a sequence, you simply take the embedding for the [CLS] token and treat it as your sequence embedding.
\end{enumerate}

\subsubsection{Loss}

\noindent
In the simplest term, `loss' is a measure of how incorrect a model's prediction input. Loss is used both in the context of a single input and sequence of input data, i.e., the average loss \cite[p.~11]{python-machine-learning}. Perhaps a more convenient way to think about loss is that it is a measure of how confident the model is in its answer; a high-loss means that model is not confident, whereas a low loss means the model is extremely confident in its answer. It should be noted that when we are optimising a machine-learning model, i.e., systematically adjusting all the weights and biases from a labelled dataset, we are not optimising the accuracy but rather loss. That is, the goal of training a neural network is to minimise the loss. Of course, in-doing so, the accuracy should indirectly improve. While accuracy and loss are not always directly correlated, if they are not it is usually indicitive of more fundamental problems.\\

\noindent
For instance, we can have a model that is extremely accurate with its answers but not very confident, i.e., a high loss. For example, if we have a classifier model and generate the final probabilities, our final answer is whichever probability is greatest. However if our model responds with probabilities that look like: $[0.25, 0.25, 0.24, 0.26]$, where each of these values is the probability of the input sequence being one of the labels in our dataset. Technically, the model has predicted our input sequence was the 4th class, as it has a probablity of $0.26$. Even if this predicition is correct, however, it is far from ideal as we would expect a perfect model, in the case of the 4th label indeed being correct, to output $[0.0,0.0,0.0,1.0]$. Obviously no model would perform \emph{that} well, but the sentiment stands that our model should be able to \emph{confidently} predict its answers. That way, we can be reassured our model is learning \emph{generalised} representations of the data and will be able to perform effectively on real-world data it has not yet seen before. In summary: not only do we want our model to be accurate, we also want it to be confident in its answer.\\

\noindent
Loss is calculated using a \emph{loss function}. Just as with activation functions, there are many loss functions, each with their pros and cons. Naturally, choice of loss function is quite an important decision when designing a model. Typically, however, there are common choices of loss functions used for particular tasks. Our task for this thesis is a multi-label classification task. That is, given some input (a code and natural-language pair) assign a label to that input corresponding to categories of security sensitive methods, i.e., source, sink, sanitiser, or none. The usual choice of loss function for multi-label classification tasks such as our task is the cross-entropy loss function\cite[p.~17]{AggarwalCharuC2018Nnad}.\\

\noindent
Exactly how cross-entropy works is quite complicated and certainly out of scope. However, for the purposes of understanding this thesis, we will treat cross-entropy as a function that takes in two probability distributions (i.e., our model's predictions versus the expected probabilities) and computes a loss comensurate to how `disimilar' the probability distributions are \cite[p.~208]{brownlee2019probability}.

\section{Support Vector Machines}

\noindent
We have spent some time discussing complex and state-of-the-art technologies for machine-learning; deep-learning and, more specifically, the transformer architecture. However, in order to see how effective this architecture is for our task, it would be appropriate to compare the performance to a `base-line' set by a older and more standard architecturefor this task. \\

\noindent
One such architecture that fits this description is the Support-vector machine architecture. Support-vector machines (SVMs) were created in the 90s and have been a standard tool for machine-learning classifications tasks ever since. For this thesis to be considered succesful, our use of advanced pre-trained models using the transformer architecture should, at the very least, be able to outperform the much simpler and older SVM architecture. \\

\noindent
SVMs are arguably the most simple learning-model for classification \cite{}. They take data, with one of two labels, and with $n$ number of features, where each feature corresponds to a dimension in an n-dimensional feature-plane, and calculate a `hyperplane' such that the datapoints from the two labels are partitioned on either side of that hyperplane in the $n$-dimensional feature-plane \cite[p.~5]{AbeShigeo2005SVMf}. Furthermore, this hyperplane is optimised in such a way that the distance between the hyperplane and the `support' data (i.e., the two datapoints, one from each label, that is closet to the hyperplane) is maximised \cite{berwick2003idiot}. Figure \ref{hyperplane-image} shows a visual representation of a hyperplane partitioning two sets of labelled data. \\

\noindent
As we will come to see later in this thesis, we will be using feature-planes with dimensions much larger than 2 or 3, such as $768$. Clearly, a $767$ dimension hyperplane partitioning a $768$ dimensional feature-plane is impossible to conceive, so this lower-dimensional analogy will have to suffice.\\

\begin{figure}
    \includegraphics[scale=0.65]{images/hyperplane.png}
    \caption{An example of a hyperplane dividing two sets of labeled data in $n=2$ and $n=3$ dimensions \cite{hyperplane}.}
    \label{hyperplane-image}
\end{figure}

\noindent
Inherently, SVMs produce a \emph{binary} classification. This is an issue for us as, for this project, we intend to perform a multilabel classification. However, even though SVMs are strictly a binary classification tool, they can be used for multilabel classification. This can be achieved through a number of techniques, but we will be using the \emph{one-versus-the-rest} technique to produce our multilabel classification\footnote{We will be using the \emph{SGDclassifier} class in the python library `Scikit' which implicitly uses the one-versus-the-rest multilabel classification methodology.}. In one-versus-the-rest classification, we create $K - 1$ binary classifiers, where $K$ is the number of labels. Each classifier classifies the datapoints as being part of the $K_{ith}$ label, or as one of the other $K-1$ remaining labels \cite[p.~182]{BishopChristopherM2006Pram}.


\subsection{Term Frequency-Inverse Document Frequency}

Term frequency-inverse document frequency (tf-idf), for the purposes of this thesis, is a methodology to extract features from data.
