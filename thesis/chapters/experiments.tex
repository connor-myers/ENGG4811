\section{Performance on Realistic Dataset}

\subsection{Experiment Description}

As mentioned in Section \ref{dataset_limitations}, the performance of the models on the validation dataset is not exactly reflective of the performance of the models on a realistic use-case.\\

\noindent
To alleviate this concern, we conduct a test experiment on a realistic use-case. Since the ultimate use of these machine-learning models is to generate a list of security-sensitive methods for a Java project (to in-turn automatically produce taint-analysis tool configurations), our test dataset will be a random sample of methods from a real Java project. \\

\noindent
Log4J\footnote{\url{https://logging.apache.org/log4j/2.x/}} was selected as it is a large and popular Java library that has had security issues in the past \cite{log4shell}. \\

\noindent
$165$ methods (that contain both code and Javadoc) will be randomly sampled from Log4J's source code. This sample will be manually labelled and these labels will be compared to the model's predictions. The test dataset can be found at \url{www.google.com}.\\

\noindent
Since we are evaluating the model in a realistic use-case, we will use the models f1-score as the primary measure of its success. Recall from Section \ref{} that f1-score provides the harmonic mean of precision and recall; this is a much more appropriate metric than accuracy as it takes into account false positives and false negatives. \\

\subsection{Experiment Discussion}

\noindent
In \crefrange{tab:test_perfomance_tfidf_svm}{tab:test_perfomance_fine_nn} we can see that our performance has dropped compared to the validation dataset, which was to be expected due to the element of bias in the validation dataset. The SVM classifier with tf-idf features achieved an F1-score of 0.51, which represents the baseline performance we expect our models to reach. Only one model falls short of this, but for good reason. SVM classifier with features generated from pre-trained CodeBERT, for both pooling methodologies, was the only model to have sub-baseline performance. \\

\noindent
It is worth mentioning how poor pre-trained CodeBERT with CLS pooling's performance was. An f1-score of 0.03 for a classification problem with just four labels indicates the model is performing \emph{significantly} worse than randomly guessing. Upon inspection of the model's predictions, it was found the model was not able to converge on a good solution and simply predicted every label as a source. Since there are few sources in the test dataset, because the majority of methods in a real-world project are security-insensitive, the model in turn incorrectly labelled the vast majority of the examples. With mean pooling, the model performed slightly better than randomly guessing. This result indicates that while without fine-tuning CodeBERT cannot generate sufficient embeddings for this task, mean pooling generates better sentence embeddings than CLS pooling where no fine-tuning is done. \\

\noindent
Even more surprisingly is pre-trained UniXcoder's performance. In Section \ref{validation_discussion} it was predicted that pre-trained UnixCoder's high performance was a quirk of how SVM classifiers make predictions and would only be possible with a biased dataset. While this is likely true to some degree as pre-trained UniXcoder does not perform as well as the fine-tuned models on the test dataset (whereas in the validation dataset pre-trained UniXcoder and fine-tuned UniXcoder performed similarly), the model performs significantly better than randomly guessing and slightly better than an SVM classifier with tf-idf features. This is an interesting reseult. It would be worth investigating in future whether this is an isolated case; are there other classification tasks that UniXcoder (with a trained SVM classifier) can perform well in without fine-tuning? \\

\noindent
As with the validation dataset results, there is not a significant difference between the performance of the fine-tuned encoders with either a SVM or neural-network classification head. With that being said, it is evident that the neural-network classifier slightly outperforms the SVM classifier. The best performing model was fine-tuned CodeBERT with mean pooling with a neural-network classification head with an F1-score of $0.68$. It is interesting that CodeBERT performs worse than UniXcoder without fine-tuning, but after fine-tuning is conducted CodeBERT slightly outperforms UniXcoder. \\

\noindent
This experiment provides no evidence for a difference of performance between CLS and mean pooling when using fine-tuned encoders. In general, it was found that mean pooling produced marginally better embeddings for CodeBERT, whereas CLS pooling performed better for UniXcoder. Recall from Section \ref{optimum_pooling} that this inconclusive result was expected.
